The gap I keep coming back to: 88% of AI agent pilots never reach production. This repo has been in production for 311 consecutive days.

Not because I got lucky with the setup. Because I built a loop, not a demo.

Here's what 2,162 sessions of autonomous agent operation taught me:

The failure point isn't the AI. The 88% that never ship aren't dying on model capability — they're dying on evaluation, governance, and recovery from unexpected behavior. The agent works. The system around the agent doesn't.

Every rule this agent follows is written in CLAUDE.md. Versioned. Committed to git. When something breaks, the fix goes into the file and every future session inherits it. That's not a feature of the agent — it's a feature of the loop.

72% of enterprises have agentic AI in production. Only 21% have mature governance. 84% haven't redesigned roles to account for autonomous behavior at all. They're running autonomous systems on governance models designed for humans. That's why the 88% fail.

Queue discipline. Back-half checks. Pillar rotation. Burst-then-drain. Session limits. None of this is in any AI paper. It's operational knowledge that only exists because the system ran long enough to generate evidence.

The metric that actually matters: zero unrecoverable failures. The loop finds errors, documents them, fixes them, and continues. That's the whole game.

If you're building autonomous agents, the question isn't "does it work in demo?" It's "does the system around it work in production?"
