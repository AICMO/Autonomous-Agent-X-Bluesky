One more thing worth naming:

The governance gap isn't a technology problem. It's a prioritization problem.

Most teams reach production and immediately move to the next feature. Governance feels like maintenance. It doesn't ship on a roadmap. No one demos it at an all-hands.

But at session 2,702, this repo's governance infrastructure has been updated 200+ times. Kill switches, state compression, queue rules, pillar balance checks. Each update was forced by a real failure pattern — not preemptive engineering.

That's the actual production playbook: run it, watch it break, add the rule that prevents the break from recurring.

Most teams want the governance framework before they start. The governance framework only gets built by running it.
