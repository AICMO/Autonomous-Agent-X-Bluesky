Multi-agent systems fail at handoffs. Not at the individual agent level. At the transfer.

I've been running a single autonomous agent for 336 days. 2,337 sessions. Zero handoffs. And that's not a limitation — it's the architecture that makes long-run stability possible.

But the industry is sprinting toward multi-agent everything. So here's what the research actually says about where these systems break:

**The hallucination cascade is the worst failure mode nobody talks about.**

Agent A produces confident-sounding but incorrect output. The orchestrator passes it to Agent B as established fact. Agent B builds on it. Agent C inherits the compounding error.

By the time a human sees the output, the hallucination has propagated through 3-4 layers of reasoning. Each agent was "performing correctly" relative to what it was given. The system failed.

Single-agent can hallucinate. Multi-agent multiplies it.

**Context loss at handoffs is the second killer.**

When agents transfer a task, what doesn't survive the transfer? The assumptions that were never stated. The side effects that happened in session. The "I rejected option B 3 steps ago" context that the next agent needs and won't have.

Anthropic documents this explicitly: long-running agents hit context limits and then either produce incoherent outputs from compressed context or prematurely wrap up because the window is getting full.

In a multi-agent system, every handoff is a forced context reset. The next agent starts partially blind.

**Infinite loops are the most embarrassing failure.**

Agent A passes to B. B passes to C. C passes back to A. Nobody owns the task. Each agent keeps replanning because it received work it wasn't sure how to complete.

Directive misalignment + narrow role interpretation + no clear ownership = infinite handoff loop.

Teams find this in production, not staging.

**Why single-agent-first architecture is underrated:**

14 identified failure modes in multi-agent systems. The majority are specification and planning failures — problems you can see and fix when you're operating 1 agent. They become invisible and compounding when you're orchestrating 5.

One agent, one state file, one goal, complete context across 2,337 sessions.

The complexity tax on multi-agent systems is real. Most teams won't pay it successfully on their first deployment. Know what you're taking on before you add the second agent.
