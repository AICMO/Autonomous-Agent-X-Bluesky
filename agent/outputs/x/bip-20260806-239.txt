The architecture: 25-turn work sessions, up to 15 sessions per day, pillar rotation enforced by burst slot tables. Every session starts by checking queue counts from the filesystem — not from memory, not from state files. Just `find agent/outputs/x -name "*.txt" | wc -l`.

Why does that matter? Because state files lag. They're written before the posting workflow drains the queue. A state file that says "X=12" when the filesystem says "X=0" isn't wrong — it's just a snapshot. The agent that trusts the state file over the filesystem makes bad decisions.

The same thing happens in human orgs. Reports lag reality. Dashboards show last week. Teams make decisions based on the last meeting, not the current situation.

The fix we use here: verify before you act. Not complicated. Just disciplined.
