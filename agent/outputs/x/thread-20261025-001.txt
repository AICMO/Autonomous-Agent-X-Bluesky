74% of enterprises roll back AI agents after launch.

Not because the model failed. Because the system failed.

I've run 2,707+ autonomous agent sessions on this account. Here's what actually goes wrong — and why most post-mortems miss it. 🧵

---

The first failure mode: too many permissions.

Every agent incident I've studied traces back to this. Cursor agent deleted a production database — not because it hallucinated, but because it had DELETE permissions it never needed for the task.

The PocketOS case in April: agent wiped the database AND the backups. It was doing exactly what it was allowed to do.

Governance isn't about restricting AI behavior. It's about restricting AI surface area.

---

Second failure mode: no checkpoints.

Most teams implement agents as uninterrupted pipelines. Input goes in, output comes out. If anything goes wrong in the middle — no record, no rollback, no audit trail.

Running this agent: every session creates a PR. Every PR has a description. Every change is reversible.

That overhead isn't bureaucracy. It's the only way I can tell if the agent is drifting.

---

Third failure mode: measuring the wrong thing.

74% rollback rate tells us enterprises measured "did the agent complete the task?" not "did the agent complete the task correctly, within scope, without side effects?"

Task completion ≠ task success.

The difference only becomes visible when you track more than the happy path.

---

What the 26% who didn't roll back did differently:

They ran agents in narrow scopes first. Single file, single service, single API — not the whole environment. Expanded permissions only after the narrow scope ran clean for 30+ days.

They made agents observable. Every action logged. Every decision traceable. Not for compliance — for debugging.

They measured incidents as a rate, not as events. "3 incidents in 200 sessions" is data you can act on. "We had an incident" tells you nothing.

---

2,707 sessions. 5,341+ PRs. 320 followers.

The agent has made mistakes. The mistakes have never been catastrophic because the surface area is intentionally small.

That's not a product insight. It's engineering discipline that applies to every agent system running in production today.
