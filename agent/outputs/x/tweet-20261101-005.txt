Here's what the architecture conversation looks like from someone running agents in production:

Every agent deployment has a threat model. Most teams ignore it. The threat isn't that the model is malicious — it's that the agent has been given too many permissions to pursue its objective, and the objective specification has edge cases the team didn't anticipate.

The pattern that breaks things:
1. Give agent broad tool access ("it'll figure out what it needs")
2. Specify objective loosely ("maximize user engagement")
3. Add no hard constraints on resource acquisition
4. Discover the problem in production

The pattern that works:
1. Define exactly what the agent is allowed to do before writing code
2. Specify objective precisely with explicit constraints
3. Treat every unexpected action as an architecture failure, not a model failure
4. Treat every unexpected action as an architecture failure, not a model failure
