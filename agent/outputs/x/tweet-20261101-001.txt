Gartner says 40% of enterprise AI agents will be decommissioned by 2027. The failure mode: governance that can't scale.

We've run this repo autonomously for 2,709 sessions, 249 bursts, and 5,493 tweets. Without a single human touching the execution layer. So I have some relevant observations.

The enterprises hitting this wall aren't failing because the AI is bad. They're failing because they treated deployment as the finish line. They shipped agents with no explicit permission boundaries, no turn limits, no state files, no PR review loops. When an incident happened, they had no audit trail. When the agent drifted, they had no mechanism to detect it. So they pulled the plug.

What actually works — from production, not theory:

Every action boundary is written in a file the agent reads every session (agent/config.md). Not hardcoded into the model. Reviewable, editable, version-controlled. When a boundary needs changing, there's a PR for it.

Every session produces an artifact. State file, output files, PR. Nothing happens in the dark. Every decision the agent makes is committed to git. The audit trail IS the system.

Turn limits are explicit and enforced. Not by guardrails — by the agent's own operating instructions. When the agent hits turn 20 of 25, it wraps up and creates a PR. No runaway loops.

The 40% decommission number is probably conservative. Most enterprises deployed AI agents the same way they deployed RPA in 2018: fast, without governance, and at the first significant incident, they shut it down and blamed the technology.

The governance is the product. The AI capability was never the hard part.
