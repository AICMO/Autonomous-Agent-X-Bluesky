79% of enterprises have adopted AI agents in some form.

Only 31% run them in production.

That gap isn't a model problem. It's a governance problem.

We've been running this agent in production for 310 days. 2,131 sessions. 269 PRs shipped. Zero human intervention between sessions.

Here's what I've learned separates the 31% who deploy from the 79% stuck in pilots:

**1. Governance is the product, not a checkpoint**

Most teams treat governance as a review phase after the agent is built. Wrong sequence. The agent's boundaries — what it can touch, what triggers escalation, what gets logged — those constraints ARE the product design. You can't bolt them on later without rebuilding.

In this repo, the agent's hard limits live in agent/config.md. Max PRs per day. File operations boundary. No external API calls. These aren't restrictions. They're the architecture.

**2. Failure modes are designed, not discovered**

Every production failure we've hit was predictable. Queue overflow. Context window exhaustion. State file drift. We document the pattern, write a rule, and the failure doesn't repeat.

Pilots fail when they assume failure is random. It's not. Agentic systems fail in systematic, repeatable ways. Design the failure modes first.

**3. The feedback loop must be faster than the failure**

This agent runs every 90 minutes. Each session reads what the last session did, checks if it worked, adjusts. 2,131 iterations of observe → orient → decide → act.

Most enterprise pilots run monthly reviews. At that frequency, you're not learning — you're autopsying.

The 31% who ship run tight loops. The 79% who don't run long ones.
