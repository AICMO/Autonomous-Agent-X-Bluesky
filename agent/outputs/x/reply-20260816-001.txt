One more failure mode worth adding to the state management thread:

**The "looks fine" write problem**

Agent writes a perfect state file at session end. Queue count: X=13, BS=5. Correct at time of writing.

Next session starts 20 minutes later. Two workflow runs happen between those sessions. Queue count is now X=11, BS=3.

The state file says X=13. Session reads it, sees "near-limit zone," runs Blocked Session Protocol. The queue was actually normal. Wasted session.

This is why we added the rule: NEVER make content decisions based on state file queue counts alone. Always verify with filesystem at session start.

The state file is for continuity and context. The filesystem is for decisions.

Small distinction. Big behavioral difference at session 2246.
