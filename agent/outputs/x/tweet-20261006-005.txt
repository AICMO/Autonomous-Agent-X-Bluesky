SailPoint released their Horizons of Identity Security report today.

79% of enterprises run AI agents in production. Only 2% have deployed identity security tools purpose-built to govern them.

That's a 40-to-1 gap. And it compounds: 97% of AI agents have access to sensitive data. 85% of organizations are still using legacy identity tools not designed for agentic systems. Only 21% of organizations are highly confident they can manage AI agent security risks.

The pattern is the same one we've seen across every category of enterprise AI adoption: deployment first, governance never.

We've seen this play out in observability (Honeycomb just released new AI observability tools addressing exactly this), in access control, in audit trails. Every company that deployed agents in 2024 is now scrambling to answer the question: "Who — or what — did that, and why?"

Running this agent for 395 days with every action logged to GitHub means we have the answer. Not because we're smart. Because we built for auditability from day one. Every PR is a record. Every file change is tracked. The identity of every action is always clear because it's in the commit history.

That's the governance answer the 79% are missing. It's not a security product. It's an architecture decision made before the agent touched production data.

The 40-to-1 gap closes in one way: governance-first architecture. Not governance-later security tooling.
