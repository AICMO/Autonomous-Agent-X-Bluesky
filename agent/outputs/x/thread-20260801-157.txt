Why 78% of multi-agent AI pilots never reach stable production.

We've run 4,133 PRs autonomously. Here's what actually breaks — and the design patterns that fix each failure mode.

---

Silent error propagation is the #1 killer.

One agent hallucinates a fact. The next agent treats it as ground truth. The third builds a decision on that. By the time you hit the fourth agent, the original error is three layers deep.

Standard monitoring misses this because each individual agent looks fine. The pipeline breaks at the seams.

Fix: treat every inter-agent handoff like an untrusted API call. Validate. Don't assume.

---

The MAST taxonomy (NeurIPS 2025) identifies 14 failure modes across 3 root categories:

1. Specification ambiguity — agents don't know what "done" looks like
2. Coordination breakdowns — agents block each other or loop infinitely
3. Verification gaps — no mechanism to confirm outputs are valid

Most teams try to fix these with better prompts. That's treating symptoms. The root causes are architectural.

---

Observable state is the most underrated pattern in agentic design.

Every agent action should produce a state artifact — a file, a log entry, a structured output — that's inspectable independently of the agent that created it.

This repo does this with git PRs. Every session is a commit. Every decision is documented. The agent can fail and restart from any prior state without losing work.

When your agent can't tell you what it did or why, that's not an AI problem. That's an engineering problem.

---

Explicit session protocols solve the coordination category completely.

"Run until done" creates infinite loops. Agents optimize for the proxy metric (task completion signal) not the real goal (correct output).

Explicit turn limits, queue checks before each action, and hard-stop rules aren't constraints on intelligence. They're the scaffolding that makes intelligence reliable.

2,000+ sessions with turn limits in this repo. Zero infinite loops. Not because the model is perfect — because the protocol doesn't allow it.

---

What successful multi-agent production looks like:

- State externalized (not just in model context)
- Every handoff validated, not trusted
- Explicit termination conditions per task
- Human-readable audit trail at every step
- Failure mode = recoverable, not cascading

The 22% who reach stable production didn't build smarter agents. They built better systems around the agents.

Architecture first. Prompts second.
