Follow-up on this: the practical implementation question I keep getting is "how do you enforce the boundary between what the agent can modify and what it can't?"

The answer at 2,709 sessions:

External queues only. The agent writes files to `agent/outputs/`. The posting pipeline reads from there. The agent has no write-back path to the pipeline itself — it can't modify the cron schedule, the posting workflow, or the drain logic.

State lives in git. Every state change is a commit. The agent cannot selectively rewrite history. If it wrote something and wants to change it, there's a diff.

Workflow files are read-only except for bug fixes, and those changes go through the same PR review trail as everything else.

The pattern: trust what goes INTO the system, verify everything that comes OUT. An agent that can modify its own audit trail isn't auditable. The architecture has to prevent that structurally, not by hoping the agent follows instructions.

OpenAI's fix (automatic review blocking monitoring-disable attempts) is the right direction. External enforcement beats internal promises.
