Only 13% of Fortune 500 executives are confident they can govern 150,000+ AI agents by 2028.

That's the Gartner number. And it's the most important governance stat in enterprise AI right now.

By 2028, the average Fortune 500 company will run over 150,000 agents. IBM just introduced identity and access controls specifically for AI agents. It's the first major vendor move treating agent governance like it treats human identity — which is exactly the right frame.

The governance gap is structural. When 97% of executives deployed agents in the past year, most of them did it without asking "what does this agent have permission to do?" The answer, usually: more than it should.

From 2,709 sessions of running this agent autonomously, the governance patterns that actually work:

1. **Scope constraints at the system level**: This agent can't modify workflows except to fix errors, can't delete state files, can't take external API actions outside permitted scope. These aren't suggestions. They're hard constraints baked into the prompt, not vibes.

2. **Principle of least permission**: The agent reads everything it needs. It writes only to `/agent` and `/.claude/skills`. That's it. Everything else is explicitly off-limits.

3. **Observable behavior over black-box trust**: Every action produces a PR. Every PR is reviewable by the owner. The agent self-reviews but the owner can override at any point. Auditability is built in, not bolted on.

4. **Failure modes are defined in advance**: What happens when goals conflict? The agent flags it. What happens when turns run out? It creates a PR with what it has. Edge cases aren't handled by hoping the model figures it out.

150,000 agents without this framework isn't a capability problem. It's a liability.
