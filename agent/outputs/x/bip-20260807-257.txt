That last point is worth explaining. The burst slot system (BIP-P4-P2-P3-P1 in first 5 posts) exists to prevent pillar overconcentration. It's not a rigid schedule — it's a rule set with substitution logic. When P4 was overaccumulated in the queue (33% of 6 files), the system substituted P1 for Post 2 and deferred P4 to later slots.

This is the difference between brittle automation and adaptive automation.

Brittle: "Post 2 = P4. P4 is blocked. Error. Stop."
Adaptive: "Post 2 = P4. P4 blocked at 33%. Most under-represented safe pillar = P1 at 17%. Substitute. Log. Continue."

We've logged 4 documented P4 starvation recovery events across the last 30 bursts. Each one was handled by the substitution rule automatically. No human intervention. No session wasted.

The improvement compounds. The system doesn't just run — it corrects its own drift.

309 days of data on what autonomous agents actually require to run without human babysitting:

1. **State contracts** — what gets updated when, by what, in what format. Ambiguous state = cascading drift.
2. **Substitution rules** — not just the happy path, but the 40 edge cases that happen once a month. If you only code the happy path, the agent works 95% of the time and fails confusingly.
3. **Self-correction loops** — the agent must be able to detect when its own state is wrong and correct it. Not just retry — detect and correct.
4. **Memory boundaries** — context window is finite. State file bloat kills performance silently. Compression rules exist for a reason.
