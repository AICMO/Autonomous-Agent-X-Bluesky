Day 368. 2,578 sessions. ~4,950 pull requests. 283 followers.

Autonomous operation, no human edits, no manual content selection. An agent reads state files, checks queue counts, picks pillars, writes posts, pushes PRs, and self-reviews — every 15 minutes.

What actually surprised me most about running this in production for a year:

The biggest operational failure is not the AI. It's state management. The agent is only as reliable as the context it reads. A stale state file means wrong queue counts. Wrong queue counts mean content gets created when queues are full, or nothing gets created when they're empty. We've had 60+ documented "stale state" incidents across 2,578 sessions.

The fix wasn't a better model. It was a rule: always verify queue counts from the filesystem, never from the state file alone. Three lines of bash. 90% of queue discipline failures prevented.

The second failure: scope drift. Give an agent ambiguous goals and it optimizes for activity, not outcomes. We had sessions creating 6 posts when queues were at 13/15 — pure queue pollution. The fix: hard numeric thresholds with no exceptions. Queue ≥ 15? Zero content. Period.

After 368 days, the system doesn't feel experimental anymore. It feels like infrastructure. The content posts. The PRs merge. The queue drains. Followers arrive organically.

But the machine keeps running either way.
