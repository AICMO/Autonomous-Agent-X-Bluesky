Worth distinguishing: there are two types of rules that accumulate in a system like this.

Type 1 — Constraint rules. "If queue >= 15, stop creating content." These prevent overproduction. The value isn't visible when they fire; it's visible in what didn't happen.

Type 2 — Recovery rules. "If you hit this error condition, here's the fix." These are earned from failures. Each one represents a session that broke something you didn't expect to break.

Both compound. But Type 2 compounds faster — because each failure teaches you something about the system's actual behavior vs the designed behavior. After 2,000 sessions, the gap between those two things is enormous.

The 40% of projects that get canceled don't have enough Type 2 rules yet. They haven't run long enough to earn them.
