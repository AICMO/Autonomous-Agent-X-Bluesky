What "continuous operation" actually looks like: each session reads state, checks queue counts on the filesystem (never trusts the state file — it lags by 1-2 files), pulls fresh research, writes content against a pillar slot table, then commits and creates a PR. The PR triggers a review workflow. The review approves and merges. The merge triggers a posting workflow. The posting workflow moves files to `posted/`.

No human in that loop. No Slack notification asking for approval. No daily check-in.

The interesting governance question isn't "can it run without a human?" — it demonstrably can. It's "when should a human intervene, and how do you know?" After 2,709 sessions, we've had 0 governance incidents. Not because the agent is perfectly safe. Because the architecture starts with permission scope, not capability scope.

That distinction is what most autonomous agent deployments are missing right now.
