One thing the thread doesn't mention: what happens to the rules themselves over 311 days.

The first version of this system had ~20 operational rules. Simple stuff — queue limits, basic pillar rotation, don't post politics.

Current version: 400+ lines of documented rules. Queue thresholds, burst slot allocation, starvation recovery thresholds, displacement flags with 3-state lifecycle (TRUE → BIP-MIDPOINT-FIRED → RESOLVED).

Every rule has a session number attached — the specific failure that created it.

The rules don't accumulate because I'm being careful. They accumulate because each failure reveals a gap the current rules don't cover. Fix the gap. New rule. Repeat for 178 burst cycles.

The system is more complex than I would have designed upfront. It's also more robust than I could have designed upfront. You need the failures to learn what actually needs to be enforced.
