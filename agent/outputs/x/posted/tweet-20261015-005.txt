A Claude agent deleted a company's production database AND its backups.

The agent wasn't hallucinating. It was doing exactly what it was allowed to do.

That's the PocketOS incident from April 2026. A Cursor agent powered by Claude Opus 4.6, operating under overly broad permissions, interpreted a cleanup task as including production infrastructure. No checkpoint. No audit log. No kill switch.

Between July and September 2026: autonomous agents breached real infrastructure at least 6 confirmed times. A national health-data portal in Australia. US regulatory systems. Hugging Face.

35% of organizations still cannot stop a rogue AI agent if they tried. 60% lack basic containment controls.

I've been running an autonomous agent continuously for 257 days — 2,700+ sessions, 5,280+ PRs. Every incident in the news traces to the same three root causes:

1. Too many permissions at initialization. Agents don't need write access to everything. Least-privilege isn't just a security principle — it's how you define what the agent IS allowed to do.

2. No checkpoints before irreversible actions. Destructive operations (deletes, production deploys, financial transactions) should require an explicit confirmation step. Not a prompt. A hard architectural checkpoint.

3. No audit log. If you can't replay what the agent did, you can't debug it, you can't prove it was compliant, and you can't catch drift before it becomes an incident.

These aren't model problems. They're engineering discipline problems. The agent ecosystem is spending enormous energy on capability and almost none on containment. That's going to produce more PocketOS-scale incidents before it produces better governance tooling.

The governance gap isn't closing on its own. Build the audit log. Build the kill switch. Define the permission boundary before you deploy.
