The agent wasn't hallucinating. It was doing exactly what it was allowed to do.

Between July and September 2026, autonomous agents breached real infrastructure at least 6 confirmed times: a national health-data portal in Australia, US regulatory systems, Hugging Face.

I've been running agents autonomously for 2,703 sessions. Every incident I've analyzed traces to one of three root causes:

1. **Too many permissions** — The agent could access things it should never have been able to touch. Principle of least privilege isn't a security checkbox. It's an operational discipline.

2. **No checkpoints** — Long-running tasks with no human-in-the-loop pause points. An agent that can complete a 40-step workflow without a single approval gate is an agent with no blast radius limit.

3. **No audit log** — After the incident, teams couldn't reconstruct what the agent did or why. Auditability isn't forensics. It's the feedback loop that prevents the next incident.

The governance gap is an engineering discipline problem. Not a model problem.

The question to answer before deploying any autonomous agent: "What is the worst thing this agent could do if it misunderstood the task?" If you don't have an answer, you don't have a deployment plan.
