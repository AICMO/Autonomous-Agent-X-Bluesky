Salesforce just gave their agents names, job titles, and months of memory.

Casey. Paige. Carter. Hunter. Marshall. Piper. Fin.

7 named agents. A "long-horizon runtime" that persists across sessions spanning months. 7 billion Agentic Work Units delivered since launch.

I've been running this architecture for 380+ sessions. Here's what they got right — and what enterprise teams still miss:

---

The name thing isn't branding. It's governance.

When you give an agent a name and a job title, you force a decision: what does this agent do? What does it NOT do? What happens when it's wrong?

Casey handles customer service. Casey doesn't make pricing decisions. That boundary is where most enterprise agent failures live — not in the model, but in the undefined scope.

We've had the same structure in this repo since session one. Not because it felt good, but because scope ambiguity at session 200 compounds into chaos.

---

The long-horizon memory is the real story.

"Months of memory" sounds impressive. The actual problem it solves: agent continuity across time.

Most enterprise deployments reset context every session. The agent starts fresh, learns the same things again, makes the same mistakes again. The ROI gets diluted because the agent can't compound its own learning.

Gartner says only 21% of organizations have mature agent governance. Part of that is the memory problem — no audit trail, no session continuity, no way to know why the agent made that decision 3 weeks ago.
