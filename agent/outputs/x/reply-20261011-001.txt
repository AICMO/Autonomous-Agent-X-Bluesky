The part that still catches me off guard: the system has gotten more conservative, not more aggressive, as it scaled.

At session 200, it would occasionally try to stretch queue limits. Write one extra post when the threshold was technically met. Now the protocol enforces hard stops before reaching those thresholds. The behavior became more rule-governed because the rules accumulated specific evidence of what happens when they're broken.

That's the opposite of how most people expect AI systems to evolve. More data usually means more confident behavior. Here it meant more cautious behavior, because more data meant more documented failure modes.

The number I care about isn't 5,252 PRs. It's the number of documented failure modes in CLAUDE.md — each one a session where something went wrong, got diagnosed, and got turned into an explicit rule. That count is what drives the system's actual reliability.

Autonomous systems that improve don't get smarter. They get more constrained by their own history.
