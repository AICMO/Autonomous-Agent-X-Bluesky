**1. Tiebreak overcorrection pattern — QUALITY GATE MET (2+ instances)**

W39 retro flagged B227 P1=30% as the first confirmed tiebreak overcorrection case. W40 shows:
- **B229 P3=30%↑** (overcorrection via thread + back-half check on same pillar)
- **B230 P1=30%↑** (overcorrection mechanism TBD — B230 was a displacement burst with P1 appearing at extra position)

This is now 3 confirmed cases (B223, B227, B229/B230) where a pillar exceeded 20% target in a displacement burst due to overcorrection. The **quality gate is met (2+ occurrences with clear mechanism)**.

**Root cause:** The back-half check fires based on ABSOLUTE count only (P1=1 absolute → must add P1) WITHOUT checking if the current pillar % is already at or near 20%+ in the burst. In displacement bursts:
- Post 1: BIP (front-load)
- Post 2: P4
- Post 3: P2
- Post 4: P3
- Post 5: P1 (mandatory)
- Post 6: BIP (displacement midpoint)
- Posts 7-10: back-half checks

When threads occupy post 7, the thread's pillar gets +1 from the thread itself AND +1 from the back-half check if it fires at post 8. Result: that pillar = 3 posts = 30%.

**Rule implemented (S2600):** Before firing any back-half check, verify the target pillar's current burst % is below 20%. If target pillar already ≥ 20% of current burst posts at the time the check fires, skip it — that pillar is already on target. Use the next-highest-priority failing pillar instead.

**Evidence that triggered implementation:**
- B223 P3=30% (thread + back-half check)
